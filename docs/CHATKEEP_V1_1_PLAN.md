# ChatKeep v1.1.0｜雙入口主網站與大型對話轉換開發計畫

狀態：**規劃確認，尚未正式執行全部批次**  
基準：v1.0.0 既有 Render 正式版保持正常運作；開發使用獨立分支／PR。  
既有初版：PR #3 `feat/local-json-extractor`，Draft，尚未驗收／合併／發布。

## 一、正式架構與功能界線

**GitHub Pages 是 ChatKeep 主網站（使用者唯一入口）；Render 是共用 Word 轉換服務。**

- **A 公開分享連結：** 使用者在 GitHub Pages 貼上 `https://chatgpt.com/share/<uuid>`，由 Render 擷取公開頁、解析並產生 DOCX。**保留 v1.0.0 已有功能**，不能退化。
- **B 官方備份：** 使用者在 GitHub Pages 選擇 ChatGPT 官方匯出的 `conversations-XXX.json`／JSON／ZIP，在**使用者瀏覽器本機**解析、建立索引、搜尋／篩選／選取對話。只把**明確選中的必要對話資料**送至 Render；Render 驗證、正規化並使用相同 Word 產生器產生 DOCX。未選取的對話不能傳送。
- **產物：** 一般情況優先提供**單一可編輯 Word**；超過經實測的安全資源界線才按**完整訊息邊界**分卷、多份 DOCX 及 ZIP。
- **JSON 不是 Word：** 本機擷取所得到的是對話 JSON；直到 Render 轉換成功才是 Word。
- GitHub Pages 只代管 HTML/JS/CSS，**不會在 GitHub 伺服器執行 JSON 解析**。Render 仍用於 Word 處理，應避免上傳數百 MB 的整包備份。
- 保護私隱：前端清楚告知本機解析與選取內容送至 Render 的分界；後端不持久化對話、URL 或本文日誌；不加入公開第三方 CORS 代理。

## 三、開發、資源與發布原則

1. **正式版隔離：** v1.0.0 Render 線上版繼續維持分享連結轉 Word；新功能於獨立分支測試，不提前影響正式站。PR #3 目前仍為 Draft。
2. **Render 免費額度優先：** 只傳選取對話、採取輸入大小／時間／記憶體／同時轉換數量限制；若超過界線應清楚停止或分卷，不讓免費服務被大量請求拖垮。
3. **內容完整性：** 以對話原始結構、當前分支與可見文字作明確區分，保留未支援內容的警告；不得暗中刪除、截斷或宣稱已完整逐訊息比對。
4. **Word 相容性：** 延續既有排版、表格、聊天泡泡與結尾段落修復；需測試 Microsoft Word 直接開啟不跳修復警告。
5. **大型備份優先桌面：** 手機對大 JSON／ZIP 的穩定性不可保證，應有明確提示與回退。
6. **測試分層：** 每批只跑對應必要測試，正式發布前一次完整回歸；不同批次不可因無關 Actions 重跑而互相阻塞。
7. **正式發布：** 第 8 批全部驗收通過後，才合併、Pages 上線、Render 手動部署並建立 `v1.1.0`；不得在尚未驗證的情況下自行宣布完成。

## 四、既有發現與待解決限制

- `word_export.py`：`rich` 版面粗略計數 > 100000 即拒絕；另外 5,000 則／500 萬字元、16 MB DOCX 限制。
- `chatkeep.py`：公開分享頁 HTML 擷取目前有 20 MB 限制，擷取連線預設 30 秒。
- `server.py`：轉換串流期限約 85 秒；目前只接受分享網址。
- `web/app.js`：前端約 90 秒中止；回應大小亦有限制。
- GitHub Pages 讀取 ChatGPT 分享頁可能受到 CORS 限制，因此**分享連結由 Render 後端繼續抓取**。
- ChatGPT 可能直接拒絕建立分享連結；因此新增官方 JSON 本機匯入路徑，不必改動原對話內容。
