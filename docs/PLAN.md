# ChatKeep 開發規劃

## 核心目標
由 ChatGPT 公開分享連結直接產生繁體中文、完整且易讀的 Word（.docx），支援手機與電腦。**不重寫、不摘要、不省略可取得的對話原文。**

## 已知基準和風險
- 已由第三方工具 GPT Export 匯出一份長對話 JSON 作研究：1,183 筆原始記錄，含 360 筆 user 文字、367 筆 assistant 一般文字及 5 筆 assistant 執行指令；732 為匯出工具所計算的可見訊息數。這些統計只能檢查匯出內容的內部一致性，不代表公開頁面毫無遺漏。
- JSON 包含空白系統訊息、內部記錄及介面標記；閱讀版必須排除無閱讀價值的資料，但原始備份應可核對。
- 介面元件例如 `box`、`row`、`text`、`AsyncImage`，可能包住 LINE 訊息正文；不能靠刪除整塊元件清理。
- 有些圖片元件僅含 query 描述而無原始圖片，不可憑空生成或假裝恢復原圖。
- ChatKeep 的「自行由分享 URL 擷取」**尚未通過實測**。先參考公開開源專案的原理並核對授權，再作正式驗收。
- 公開 GitHub 只存合成、去識別化測試素材；**不得提交真實對話、私人 JSON、下載 HTML 或秘密金鑰**。

## 第 1 批：獨立分享連結解析器
1. 輸入公開 `https://chatgpt.com/share/...`，限制可信主機，安全下載 HTML。
2. 辨識支援的分享頁資料格式；安全解析內嵌資料串流／跳脫內容／資料參照及舊版格式（確定存在才實作）。
3. 依對話樹還原順序、角色、訊息，輸出穩定的 JSON 結構。
4. 建立解析報告：原始訊息數、可見訊息數、角色分布、空白資料、分支、警告及無法處理欄位。
5. 對格式變更、HTTP 錯誤、逾時、不完整片段明確報錯，不將部分結果冒充完整成功。

**驗收**：用合成測試涵蓋中文、跳脫字元、長對話、分段資料、異常情形；測試公開分享連結並逐訊息與研究基準比較。不得只因 732 筆對上便宣稱完整。

## 第 2 批：內容語義還原
安全解析 Markdown／UI 元件，保留 LINE 人名、時間、對話順序；保留標題、清單、表格、超連結、真實程式碼及數學內容；消除無用介面編碼。圖片只有取得真實資產才嵌入，否則清楚註記。

**驗收**：可見文字逐段核對，元件內正文不遺漏；禁止執行來自分享網頁的任意程式。

## 第 3 批：Word 排版
小說閱讀型：繁體中文字型、使用者／助理區分、場景時地、LINE 訊息樣式、頁碼、導覽標題及避免孤行；效能要能處理數百則以上長文。

**驗收**：可選取、編輯、搜尋的 docx；文字及順序核對；超長文件實測。

## 第 4 批：網頁與部署
手機直向／桌機支援、單一連結輸入、狀態及缺漏報告、Word／JSON 下載。GitHub Pages 只支援靜態前端，需要遠端擷取時應評估安全可維護的後端／Serverless。

## 第 5 批：整合與安全驗收
模擬格式變動、壞資料、URL 白名單繞過、SSRF、過大輸入、下載失敗及暫存清除；最小必要 CI 和跨裝置實測。

## 開發界線
不動 franksky1207/rpg。不購買或大量使用第三方擷取額度。首次建立後端／付費服務須先向使用者說明。
