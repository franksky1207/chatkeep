# ChatKeep｜現役開發規格與驗收計畫

> 此文件為 ChatKeep 現行正式規劃。先滿足產品契約與最小完整流程，不為湊數而硬分固定批次、Actions 或 PR。本文為規劃，不表示功能已完成。

## 1. 使用者體驗與產品邊界

- **輸入**：使用者有權分享的公開 ChatGPT 分享連結（`chatgpt.com/share/...`）。
- **輸出**：可搜尋、可編輯的繁體中文 Word `.docx`，自動以對話標題命名；進階功能可下載原始或正規化 JSON。
- **完整操作**：貼連結 → 擷取 → 完整性檢查 → 語義／視覺還原 → 顯示警告與統計 → 下載。除連結外不要求 GPT Export、外掛、API Key 或 ChatGPT 登入；不能讀取時要明確告知，不得假成功。
- **裝置**：桌機／手機並重、響應式設計、功能一致，無須維護兩套獨立介面。
- **非目標（首版）**：登入帳號、永久對話雲端資料庫、批次大量抓取、付費擷取服務、互動 Word 按鈕／即時圖表。前期不添加不必要系統。

## 2. 不可妥協的內容契約

1. 保留可取得的 user／assistant 訊息原文、順序、分支路徑；不摘要、不改寫、不更正原文錯字／標點，不自動補出缺失內容。
2. 區分原始訊息總數、實際可見訊息、系統／工具／內部記錄、空白片段、無法處理的互動和附件。只比對數量不足以證明完整；逐訊息驗證 ID、角色、順序與原文，必要時對正規化結果做文字雜湊核對。
3. **先解析元件結構，後移除工程噪音**：`box`／`row`／`text`／`caption`／`{@body ...}` 等可能內含正文、選項與名稱；不得以單純正則刪除整段。原始備份不被閱讀版清洗覆蓋。真實程式碼區塊應保留。
4. 保留標題、清單、表格、連結、公式、角色區分與圖片資訊；缺少真正圖片資產時只能留下可讀註記和警告，不以生成圖片冒充原圖。
5. **語義還原優先，視覺適度還原**：Word 不需模仿所有 CSS 或動態效果，但必須保留可閱讀內容、群組、順序與重要版面關係。優先使用 Word 原生元素，保持可編輯。

### Word 元件映射

| ChatGPT 內容 | Word 正式呈現 | 驗收重點 |
| --- | --- | --- |
| `<box>`／資訊卡 | 有底色／邊框的段落、方框或儲存格 | 內文完整、層次清楚 |
| `<row>`／多欄 | 原生表格／儲存格對齊 | 語義順序與分組正確 |
| `<text>`／`<caption>` | 文字樣式、大小、顏色及附註 | 字符不遺漏 |
| LINE、私訊 | 可編輯的左右聊天泡泡（表格底色）、人名、時間 | 文字、發言者、順序、左右位置正確 |
| 表格 | Word 原生表格 | 儲存格與內容一致 |
| 按鈕、選單、單選／複選 | 靜態選項列表或方框 | 顯示文字保留；不宣稱互動可使用 |
| 真正程式碼／數學 | 程式區塊、可閱讀公式 | 文字與符號完整 |
| 真正的圖片 | 取得合法可用資產後嵌圖 | 不替代、不杜撰 |
| 僅含 `AsyncImage query` | 原圖片不可取得的文字註記 | 明確標示未還原 |
| 動態圖／未知元件 | 可信靜態表示、資料表或可讀警告 | 不默默丟失 |

元件三級驗收：**內容正確（字不缺）／結構正確（人名、群組、排序）／視覺合理（跨頁及尺寸）**。優先使用 Word 原生表格、底色、框線與文字樣式，避免整頁截圖導致不可編輯。

### 排版

一般問答清楚區分角色；敘事內容可採緊湊小說式場景標題；技術內容保留程式碼、表格與公式。全文不強制小說樣式。頁碼、Word 導覽標題、合適段距、跨頁防孤行；不強制每一回合換頁。標題自動命名。

## 3. 已知研究基準（不是成功宣告）

由 GPT Export 產生的研究 JSON 曾觀察到：**1,183 筆原始記錄**，其中 360 筆 user 文字、367 筆 assistant 一般文字、5 筆 assistant 執行指令，第三方計數為 732。還有系統／工具／內部資訊。資料結構和可見訊息定義須再以正式解析器實際驗證；**不得把 732 當成 ChatKeep 擷取成功的證據**。原始研究 JSON／Word 含私人資料，不可提交至公開 GitHub。元件內有 LINE 實際文字，圖片 `query` 不等於原圖。

## 4. 開發階段與交付條件

### 階段 1｜最小可用垂直切片（第一個技術 Gate）
- 先研究且確認開源方案授權、實際分享頁內嵌資料格式，實作可維護的安全 HTML 擷取與 parser（串流、參照、跳脫、對話分支）。
- 建立**單一正規化訊息模型**，擷取器、轉換器與 Word 共用同一正式資料來源；統一錯誤、警告、統計。
- 先證明**不依賴 GPT Export 的直接擷取**；再接一個最小介面／基本 Word 下載，讓使用者走完貼連結到下載的完整流程。
- 此階段只做必要的基本 Word，不提前完成全部元件視覺樣式；可以用合成 fixture 開發，私人真實測試資料不得進 Git。
- **驗收**：真實公開分享連結有可重現端到端測試，與已提供的參考 JSON 逐訊息比較；下載 .docx 可開啟、內容與角色順序可核對。直接擷取失敗就視為 Gate 未通過，不宣稱 MVP 完成。

### 階段 2｜語義解析與 Word 原生元件
- 安全解析 Markdown、介面元件樹、嵌套內容、選項、LINE、表格、圖片參照。
- 以 Word 原生方框／儲存格／聊天泡泡做靜態替代，保留內容；不執行任何外部嵌入腳本。
- **驗收**：針對 box、row、caption、LINE、表格、真正程式碼、無圖圖片元件使用合成測試，逐字／結構／視覺三級核對，無可見正文丟失。

### 階段 3｜排版、跨頁與長文效能
- 一般對話／敘事／技術內容有合適閱讀型排版，標題、頁碼、目錄／導覽和中文樣式一致。
- 測短、中、超長篇，驗證跨頁、文件可編輯、生成時間、記憶體與輸出容量。
- **驗收**：可編輯、可搜尋、字元核對與可讀版面，不因跨頁或 UI 元件導致文字消失。

### 階段 4｜公開網站與部署
- 同一套響應式介面覆蓋桌機和手機；顯示轉換進度、訊息數、缺漏／圖片警告，主下載 Word、進階下載 JSON。
- GitHub Pages 只做靜態前端；若需要後端／Serverless，先評估部署、隱私、成本與維護。不自動購買服務。
- **驗收**：網站可透過公共網址直接使用，桌機／手機功能一致；暫存清除、明確錯誤提示。

### 階段 5｜整合、安全與正式發布
- HTTP 失效／逾時、格式變動、巨量輸入、惡意 URL、SSRF、惡意嵌入、下載失敗、中斷／重試、資源回收。
- CI：L1 每次變更快速預檢、L2 受影響功能回歸、L3 涉及 UI 才跑瀏覽器跨尺寸、L4 整合／正式發布確認 Gate。只取消同 PR 過時 Actions；不為綠燈跳過保護。
- 分別確認提交、PR、main、Actions、正式部署與桌機／手機實測，紀錄對應 SHA。
- **驗收**：按風險測試、正式網站完整流程與缺漏處置，沒做過的測試不宣稱已通過。

## 5. 開發協作／治理規則（源自《文明戰線》反思，僅取通用部分）

- 每個工作契約包含：目的、現況證據、修改範圍、正式規則、例外、不得修改、可量化驗收。
- **規格先行、先樣本後擴展、共用核心與單一 owner**；解析、內容轉換、Word 輸出責任明確，資料模型共用，勿重複維護各套轉換。
- 工作批次以依賴和風險決定，不強制五個 PR；小改由 ChatGPT＋GitHub，跨模組或較大量測試交 Codex。沒有授權不自行開工；「直接完成整批」則不能無故半途停工。
- 不建構帳號、資料庫、複雜 CI 或多個工具平台來取代本產品的核心流程；依量測證據優化。
- 現役文件以 README／本文為主要來源；決策／歷史以 Issue、PR、Git SHA 可追溯，避免產生大量過期規劃文件。
- 公開程式碼不代表公開使用者對話。禁止提交真實私人 JSON、Word、HTML、金鑰；正式轉換預設不保存，紀錄不包含對話正文。
