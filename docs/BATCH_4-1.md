## 進度設計契約

**不顯示虛假的總百分比。** 每個階段獨立 0–100%，切換時前階段進度立即消失。
- fetch：若來源提供 `Content-Length`，用已下載位元組／總位元組；否則顯示位元組數與「正在擷取」但不顯示百分比。
- parse：資料串流解碼時無進度計數；正式節點正規化期間以已處理／總節點計算。
- word：每完成一段訊息轉換就累計；不是按時間估算。
- pack：沒有可靠的封裝進度則只顯示「正在準備下載」。
- done：檔案已完整抵達瀏覽器可下載時，隱藏進度區並顯示下載欄位。
- 失敗／中止：不冒充完成；顯示錯誤並隱藏過期下載檔案。

## 部署架構（本批僅準備，不正式部署）

目前 Python `server.py` 是**loopback 本機開發伺服器**，不直接曝光公共網路；正式服務不能只靠 GitHub Pages，因為 Python 分享頁擷取需要同源後端，且 ChatGPT 不保證提供允許瀏覽器跨來源讀取的 CORS 標頭。

第 5-1 批需決定採用支援 Python 的單一網頁／後端部署平台（優先具 HTTPS、可用串流、對話資料不落地、免費額度可行，且不擅自啟用收費資源），或靜態前端與同源反向代理後端的簡單組合。正式外網版應追加速率限制、限制同時轉換與上傳大小、CORS／CSRF／DNS 及超時防護，檢查隱私政策和錯誤紀錄；**未落實前不可直接用 `--host 0.0.0.0` 對外發布。**
