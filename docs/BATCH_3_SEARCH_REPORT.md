# ChatKeep v1.1.0｜第 3 批：搜尋、選取與索引完整性報告

此批只在前端索引資料上加上標題、日期、系列編號區間的交集篩選；不修改 JSON／ZIP 串流解析、原始位元組定位、Render 或 Word 產生器。資料仍只在使用者瀏覽器處理。

## 功能
- 可輸入標題文字，依建立／更新日期（UTC）篩選。
- 系列名稱 + 起訖編號，例如「文明戰線 1～101」「高中導師遊戲 1～9」。支援阿拉伯數字與一般中文數字、全形括號；避免將「文明戰線外傳 1」誤判。
- 搜尋結果全選包含超過畫面前 300 筆的所有符合對話；取消選取保留。
- 單筆預覽僅展示索引中既有的標題、官方 ID、日期、來源、原始 mapping 節點欄位數、位元組範圍，不讀取本文。
- 報告顯示索引總對話、目前符合對話數、目前符合節點欄位數、來源數、已選數、指定編號區間缺號、同編號重複及部分來源解析失敗。

## 語意界線
- 「缺號」是**已成功匯入、目前篩選結果**的編號覆蓋狀況，不是證明原始備份完整或缺少一段聊天。使用日期／文字交集篩選時，區間可能因此出現缺號。
- mapping 原始節點數不等於可見訊息數，也不等於可匯出訊息數。這一批未走訪 current_node、分支或訊息內容，故**可見／可匯出訊息數一律標記未驗證**，不虛報。
- 重複編號可能是不同對話，不能擅自合併或去重；單筆擷取仍由第 2 批原始 Blob 範圍處理。
- 超過 300 筆只限制畫面渲染，不限制搜尋、選取或統計。
- 僅篩選頁面新增內容，不提供 ZIP/DOCX 輸出，亦不呼叫 Render 新端點。
