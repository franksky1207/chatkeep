# ChatKeep v1.2.0｜第 3 批驗收紀錄（尚未發布）

日期：2026-10-28

## 現況
- v1.1.0 正式站與 Render 維持原狀，v1.2.0 只在 `feature/v1.2.0-local-html-reader`。
- JSON 本機解析、閱讀、搜尋、含格式分批複製及 HTML/ZIP 下載已實作。
- 分享連結 HTML 擷取端點 `/api/share-reader-v1` 與前端共用閱讀器已實作，**尚未部署 Render**。
- 新增修正：原先閱讀器複製按鈕版面誤將搜尋/分頁包進隱藏容器，已修復。
- Word 轉換既有 API 維持原路線；仍要做上線前回歸。

## 已驗證
1. Chromium（合成 JSON）進行索引、對話閱讀、搜尋、含格式剪貼簿、HTML/ZIP 下載、切換功能頁。
2. Chromium 模擬分享內容 API，驗證分享網址模式能開啟相同閱讀器（非真實 Render 網路成功證據）。
3. Python 分享解析單元測試：僅傳可見對話，非法網址拒絕，未產 DOCX。
4. Node 內容與 ZIP 完整性測試：含表格、HTML 跳脫、CRC 解壓驗證。
5. 壓力測試：1,800 則合成對話 HTML 分卷重組保序；1,500 則合成訊息複製分批完整性。

## 尚未通過，因此禁止直接發布
- 真實分享連結 → 獨立測試 Render → HTML 閱讀器端對端驗證。
- 真實分享連結 → 舊 Word API 回歸（不可因新版端點而改壞）。
- 使用者真實九段對話：首尾、字數、HTML 單檔/ZIP、貼入 Word 儲存及重新開啟的人工驗收。
- 手機/不同瀏覽器效能差異與安全限制實測。
- 需確認上線環境 `CHATKEEP_ALLOWED_ORIGINS` 涵蓋正式 Pages 網域與預覽策略，並檢查無快取及無認證資訊要求。

## 發布原則
先完成隔離環境端對端驗收、修復必要問題，取得使用者確認，再一次合併 main、發布 Pages 與 Render。不可將測試成功的模擬 API 描述為 Render 已成功部署。
