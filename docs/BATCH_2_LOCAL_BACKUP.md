# v1.1.0 第 2 批：大型官方備份本機索引

範圍依 `CHATKEEP_V1_1_PLAN.md` 第 2 批，基於 `7ee7f4c`。只修改 Pages 前端、相應測試及本文件；不修改 Python 後端、`web/`、依賴清單、Render 設定或 Actions。不包含進階搜尋、JSON → Word API、跨服務整合或發布。

## 資料流程與完整性

1. `docs/index.html` 保留雙入口與既有 Render 連結，載入同站點的 ES modules。沒有 CDN、第三方函式庫或新依賴；四個模組未壓縮合計約 29 KiB。需透過 HTTP(S) 網站或本機 HTTP server 開啟，不能保證直接 `file://` 開啟或離線重新造訪可用。
2. `local-backup/app.mjs` 管理唯一操作、搜尋／選取、下載與清理。索引用「來源編號 + 原始起始位元組」識別，重複標題、甚至重複官方 ID 均不合併。清單只渲染 300 筆，但「勾選目前搜尋結果」包含全部符合項目。
3. `worker.mjs` 逐來源處理。`json-index.mjs` 以 256 KiB `Blob.slice()` 讀取；增量詞法分析器處理字串、跳脫與數字，搭配明確的物件／陣列語法狀態堆疊。這不是單純計算大括號。串流 `TextDecoder` 使用 fatal UTF-8 驗證，正確處理跨塊多位元組字元。
4. 支援頂層對話陣列及既有 `{ "conversations": [...] }` 包裝。對話需有物件型態的 `mapping`；標題／ID／時間型態異常、重複索引欄位、損壞語法或不支援結構會明確拒絕該來源，不靜默跳過。空陣列合法；空檔不合法。UTF-8 BOM 不支援，會回報位置；不猜測其他文字編碼。
5. 只保留標題、官方 ID、時間、mapping 第一層成員數、來源及原始 **UTF-8 位元組** `[start,end)`。不建立或持久保留 mapping 物件，也不走訪 `current_node` 來丟棄分支。畫面明確標示「原始 mapping 節點欄位（非可見訊息數）」；不宣稱已驗證可見訊息完整性。
6. 來源須完整掃描至 EOF、驗證成功，才分批傳回索引。尾端損壞會使整個來源失效，不留下看似有效的半份索引；其他有效 JSON 可繼續使用。ZIP 則以各 JSON 項目為失敗隔離單位。
7. 下載直接取保留的 `File`／暫存檔案範圍，回傳 `Blob.slice(start,end)`，**不重新 JSON.parse／JSON.stringify 對話**。保留原始空白、跳脫、數字字面值、未知欄位、非文字內容、工具／隱藏節點與所有分支。單一物件範圍與來源位元組一致；不包含外層陣列、分隔逗號或 ZIP 壓縮位元組。測試另以結構比對及 SHA-256 核對此聲明。

## 記憶體、取消與資源界線

- 原始 JSON 的工作緩衝為一個 256 KiB 區塊、UTF-8 解碼暫存、有限詞法 token 與深度堆疊；不隨 mapping 本文大小增長。`JSON.parse` 僅用於解碼已限制大小的索引字串，不用於整包或完整單一對話。
- 每次最多 200,000 段、索引估算預算 64 MiB（每筆固定估算開銷 + 標題／ID UTF-16 大小）。這是索引預算，**不是整個瀏覽器的記憶體硬上限**；Worker 傳回當前檔案索引時會有短暫複本。
- 索引字串 token 上限 64 KiB、數字／常值 token 1,024 bytes、巢狀深度 2,048。超限直接說明並拒絕該來源，不截短內容後冒充成功。極端長標題／未知頂層鍵也可能觸及字串上限。
- 掃描／下載鎖定會改變來源或選取的操作。取消先通知 Worker，在下一個分塊檢查點中止並關閉檔案；2 秒無回應才終止 Worker。清理等待寫入鎖釋放，若仍失敗明確提示清除網站儲存空間。操作世代編號使舊訊息／下載結果失效。
- 取消、清單重設、來源失敗會清除相應暫存；成功 ZIP 的暫存保留到清單重設，讓後續擷取只需讀指定範圍。分頁關閉會嘗試清理，但瀏覽器崩潰／強制結束無法保證，介面提供網站儲存空間清理指引。不會刪除其他分頁的目錄。
- Blob 下載網址在重設或 60 秒後撤銷；多檔下載仍受瀏覽器許可與政策限制。已交給瀏覽器的下載不能由「取消操作」收回。

## ZIP 方法與限制

- 自行解析 ZIP32 EOCD、中央目錄、本機標頭及可選資料描述符；檢查檔名、旗標、大小／CRC 宣告、偏移、區間不重疊及目錄邊界。只處理路徑末端的 `conversations.json`／`conversations-<數字>.json`，其他項目只檢查結構，不解壓。
- 支援 stored、deflate；壓縮輸入也固定最多 32 KiB／次，使用瀏覽器原生 `DecompressionStream('deflate-raw')`。逐項輸出到 OPFS Worker 同步檔案 handle，每次寫入最多 256 KiB，關閉後取得 `File` 建立位元組索引。ZIP 的原始路徑不會用作本機寫入路徑。
- 實際解壓量、宣告大小及 CRC32 全部核對後才建立索引；CRC32 是損壞檢查，並非來源身分驗證。超過宣告大小立即停止，不依賴不可信的目錄大小分配整個 buffer。
- 拒絕加密、多磁碟／分卷、ZIP64、其他壓縮法、重複對話檔名、異常結構、超過 200 倍壓縮比例。單項 < 4 GiB、單個 ZIP 對話總量最多 8 GiB，並檢查瀏覽器剩餘 quota；對話 JSON 檔名每項最多 4 KiB、合計 4 MiB、最多 10,000 項。這些是防護界線，**不表示已實測 4／8 GiB**。
- ZIP 需要安全來源、OPFS、Worker 同步 access handle 與原生 deflate-raw；功能／空間不足時說明先在電腦解壓後直接選取 JSON。拒絕 OPFS 不會阻擋獨立 JSON。一般瀏覽的 OPFS 可用磁碟暫存；私密／無痕模式可能把暫存放在記憶體，大檔建議一般模式。沒有額外伺服器或線上解壓服務。

### 440 MiB 壓力測試：已實際執行

每個 JSON 恰為 **461,373,440 bytes（440 MiB，約 461 MB）**。資料包含可壓縮重複段落及每筆不同的確定性合成內容，沒有整份備份緩衝。第一種 3,505 段對話；第二種一段含 3,516 個 mapping 成員的大型對話。ZIP 的解壓 JSON 同為 440 MiB，壓縮檔 48,003,691 bytes。

| 一般瀏覽目標 | 掃描時間 | 程序 RSS 基線 → 峰值 MiB | 匿名 RSS 基線 → 峰值 MiB | 主畫面 50 ms heartbeat 最大間隔 |
|---|---:|---:|---:|---:|
| 440 MiB、多對話 JSON | 7.90 s | 820.2 → 875.1 | 410.2 → 464.7 | 72.6 ms |
| ZIP → 440 MiB JSON（解壓＋驗證＋索引） | 11.96 s | 829.4 → 921.8 | 411.1 → 505.4 | 52.8 ms |
| 單段 440 MiB mapping | 7.41 s | 779.0 → 821.0 | 359.0 → 412.0 | 60.8 ms |

RSS 每 100 ms 讀取 `/proc`，加總 Python 測試程序的子程序（Playwright driver、Chromium 及子程序），不含 Python 生成器。共享頁可能重複計算；這不是私有 V8 heap、作業系統硬上限或下載期間獨立峰值，也可能漏掉短於採樣間隔的峰值。介面 heartbeat 在所有掃描期間持續運行。

首／中／末筆 JSON 擷取、ZIP 中段擷取及整段 440 MiB 單對話下載皆以來源範圍 SHA-256 比對通過。小型 fixture 另做 `JSON.parse` 後的完整結構比對。掃描開始後取消約 0.057 秒完成；ZIP 實際解壓中取消後驗證 OPFS 目錄為空，重掃成功。

私密測試 profile 的同一 ZIP 曾觀察 RSS 約 763 → 1,280 MiB、匿名 RSS 約 374 → 906 MiB；**不能把一般瀏覽模式結果推廣至無痕模式或低記憶體手機**。程式不把整包資料存進 JS 陣列／字串，但瀏覽器自身的儲存實作仍會影響記憶體。
