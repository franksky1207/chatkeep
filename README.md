# ChatKeep｜對話收藏

**讓每段對話，都能好好保存。**

ChatKeep 是公開開發的 ChatGPT 對話典藏工具：使用者貼上**公開的 ChatGPT 分享連結**，網站直接擷取與驗證內容，輸出完整、好讀、可搜尋與編輯的 **Word（.docx）**。繁體中文（台灣用語）；桌機與手機**並重、功能一致**，使用響應式介面。

## 最終使用體驗

貼上分享連結 → 自動擷取與核對 → 語義和視覺還原 → 顯示訊息數／警告 → 下載 Word。自動用對話標題命名。JSON 可作為進階備份選項，不是使用者必經步驟；不要求安裝外掛、使用 GPT Export、ChatGPT 登入或 API Key（以連結本身可公開存取為前提）。

## 產品契約

- **逐字保存**：不摘要、不改寫、不補寫、不自行更正原文；依分享頁實際可取得的訊息保留發言者與閱讀順序。
- **可驗證的完整性**：區分原始記錄、可見文字、非文字互動、工具／系統資料與分支。不能只因筆數相同就宣稱完全一致。缺漏要指出位置和原因；部分成功不可冒充成功。
- **語義還原優先、視覺適度還原**：把 ChatGPT 介面描述解析成內容與結構，**不能直接刪除包含正文的元件**。盡量採 Word 原生文字、表格、儲存格底色與框線，保留可編輯性。
- **元件對應**：`box`→方框或有底色段落、`row`→表格／對齊、`text`／`caption`→樣式、LINE→具人名／時間／左右位置的聊天泡泡、按鈕／選單→靜態選項。互動行為本身無法在 Word 中執行。
- **內容類型通用**：一般問答、小說敘事、技術討論、程式碼、標題／清單／表格／連結／數學內容皆能閱讀；不把所有對話強制排成小說。真正的程式碼應保留，UI 實作噪音應移除。
- **媒體誠實性**：只嵌入實際取得且有權使用的圖片；純 `AsyncImage query` 不等於原圖，不產生替代圖片冒充。
- **隱私**：公開 GitHub 只有程式與合成測試資料，不提交真實私人對話、憑證或原始擷取頁；正式轉換預設不建立對話資料庫，伺服器暫存應盡速清除。

## 工程策略

採用《文明戰線》工程反思的有效原則：**需求契約、單一正式來源、最小可用垂直切片、按風險分層測試、少量樣本先驗收、集中整合發布**。批次按依賴與風險切分，**不強制五次 PR**。小修改可由 ChatGPT＋GitHub；跨模組開發／大量測試交 Codex。僅在明確授權後施工；「先討論」不動程式。

## 開發階段

1. **最小可用流程（MVP）**：先通過直接擷取分享頁的技術門檻，再串接基本 Word 下載形成完整垂直切片。
2. **內容與 Word 原生元件還原**：Markdown、UI 結構、LINE／表格／方框／選項，並進行內容、結構、視覺三級驗收。
3. **正式排版與效能**：閱讀型排版、導覽、跨頁、超長文件效能。
4. **公開網站與部署**：桌機與手機完整支援、狀態、警告、下載、部署與隱私管理。
5. **整合驗收與發布**：分級 CI、異常恢復、安全性、正式環境與實機驗收。

以上是工作階段而非固定 PR 數量；詳見 [開發計畫與驗收](docs/PLAN.md)。

## 本機啟動

需要 Python 3.10+：

```sh
python -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python server.py
```

在執行機器開啟 http://127.0.0.1:8000 ，貼上公開分享連結，查看統計與警告後下載 Word。對話只在請求記憶體中處理，不保存於伺服器、不記錄正文。正式 WSGI 啟動可用 `gunicorn --config gunicorn.conf.py server:application`；`render.yaml` 只是準備，不代表已部署。這是本機驗證版；若在遠端環境執行，需使用該環境支援的預覽／轉送方式。

```sh
python -m unittest discover -s tests -v
```
